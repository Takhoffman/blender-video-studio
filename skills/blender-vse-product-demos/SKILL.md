# Product Demos

Identify the audience, one primary benefit, and the actual result visible in the supplied assets. Establish what the product does before adding decorative motion. Never fabricate UI states, functionality, performance, or outcomes.

Build a compact problem → action → result sequence. Remove loading and navigation dead time when appropriate, but mark time compression if elapsed time supports a performance claim. Keep enough cursor or touch context for the viewer to follow the action. Do not show an unexplained result before the input that produced it unless the opening is an explicit preview.

Inspect screen recordings at intended delivery size. Reframe to relevant controls; use stable close-ups and eased focus changes rather than constant zooming. Hold a completed state long enough to read it. Add an accurate callout only where the existing interface is insufficient. Avoid covering the cursor target with captions.

Use supplied clean demo data; flag exposed private information and mask or replace it within the authorized output. Do not alter the live product or send forms/messages just to obtain footage unless authorized. Prefer provided recordings or a safe demonstration environment.

A polished demo can use a device frame or spatial animation when it clarifies context; it does not need one by default. Pair narration with the corresponding visible action. Keep music beneath useful speech and interface sounds.

Handoff: final video, editable project, and the depicted workflow/source ranges. Review whether a first-time viewer can identify the benefit, follow the clicks, and read the result without pausing.

Use [Blender Video](../blender-vse-video/SKILL.md) for version-aware execution, [Audio & Sound Design](../blender-vse-audio-sound-design/SKILL.md) when mixing, and [Video Review & Delivery](../blender-vse-video-review-delivery/SKILL.md) before handoff. Preserve the brief’s duration, style, format and source constraints; these are editorial guidance, not a fixed template. Follow source inspection → plan → scripted timeline → preview → inspection → revision → final render.
